---
name: level-up
description: Move the project to GitHub and put the page online. Once per project.
disable-model-invocation: true
---

You can't click anything in their browser. Give one step at a time, say exactly what they should see, and wait for "done" before the next step. If a screen doesn't match, ask them to describe it or send a screenshot.

1. Check that version 1 works and is saved. If not, suggest finishing first.
2. Explain in three sentences: GitHub stores the project online and keeps every version. GitHub Pages turns the docs folder into a live link. On a free account the project is public, so anyone with the link can read the files, including notes and reviews.
3. Privacy check of every file that will be uploaded (CLAUDE.md, NOTES.md, HABITS.md, reviews/, docs/). List anything private and fix it with them before going on. For each photo in docs/, ask if it came straight from a phone. If so, have them drag a screenshot of it into docs/, set the original aside, and point the page at the new file.
4. GitHub account: open github.com/signup in their normal browser. "Continue with Google" or Apple is fine. Their username will be in the page's link, so pick one they're happy to share. Verify the email.
5. Make their project from the template: open the template link in the brief's footer, click "Use this template", then "Create a new repository". Name it (for example my-page), choose Public, click "Create repository from template".
6. Update "Where it lives" in CLAUDE.md to "GitHub: <username>/<repo-name>". Leave Session number as it is: the cloud session they start at the end is still this session, not a new one, and /wrapup there adds 1. Also add "commit", "branch" and "GitHub Pages" (plus any other word you'll use in steps 7 to 10) to "Words I've learned" now, with a one-line meaning each, since nothing written in this folder after the upload reaches GitHub, and add a line to the log in NOTES.md: "Level 2: moved to GitHub, live at https://<username>.github.io/<repo-name>/." Add one line under "Today" for each notable move so far, starting with the session number (for example "S2:"), so the review in the cloud session can use them. Also write any habit counts or traps you're still holding into HABITS.md now, and add one "Today" line with this session's counts so far, for example "S2 counts so far: plan 0 own/1 reminded; check 1/0; save 0/1; goback 0/0". Also add a "Today" line "S<N>: /level-up in progress, next step 7" (it goes up with the files, which does no harm). Do this before the upload so it goes with it. (Ask permission like any file change.)
7. Upload: first offer to open this project folder for them in Finder (Mac) or File Explorer (Windows). That takes one permission box (if it doesn't open, use the level 1 fallback in .claude/CLAUDE.md). In the new repository click "Add file", then "Upload files". From inside the project folder, drag in CLAUDE.md, NOTES.md, HABITS.md and the reviews and docs folders. Don't drag the project folder itself: that puts everything one folder too deep. Don't upload versions or set-aside. Click "Commit changes". Then ask them to click CLAUDE.md on GitHub and check two things: "Where it lives" says GitHub:, and their own answers are there. If they see blanks (____), the upload went wrong. Upload the files again from inside the folder. Then remove the misplaced extra folder, because it also holds versions and set-aside, which weren't privacy-checked: open that folder on GitHub, click the three dots (...) at the top right, choose Delete directory, then Commit changes. Their files are still safe in the folder on their computer. If versions/ or set-aside/ there held something private (for example the original phone photo from step 3), tell them GitHub's history still keeps a copy. The only full fix is to delete the repository (Settings, bottom of the page, Delete this repository), make it again (step 5) and upload again (this step). Step 6 is already done: only if they pick a different name, change "Where it lives" and the "Level 2: ... live at" log line in NOTES.md in that same change. Once CLAUDE.md looks right on GitHub, the notes and scorecard have gone up. For the rest of this session here, don't count habits or note moves, and don't ask them to remember any for /wrapup. Praise good moves in the moment instead.
8. Turn on the site: Settings, then Pages, then under "Build and deployment" choose "Deploy from a branch", branch main, folder /docs, Save. It can take up to ten minutes.
9. Their link is https://<username>.github.io/<repo-name>/ . Ask them to open it on their phone.
10. Connect GitHub to Claude: open claude.ai/code in the browser and follow the "connect GitHub" prompt. If it offers to install the Claude GitHub App, install it on this repository only.
11. Tell them: from now on, work in a new session with environment Cloud and this repository, on the computer or the phone. This folder on the computer is now the old copy. After this session, rename it to "my-page (old copy)" and don't build in it anymore. Don't change anything in this folder after the upload: it won't reach GitHub.
12. Don't change any more files in this folder, and don't /save or /wrapup here: nothing written here reaches GitHub now. Say: "Start the new Cloud session now. Type /pickup, make one small change, /save it, /ship it, then /wrapup there."
