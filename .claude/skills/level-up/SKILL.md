You can't click anything in their browser. Give one step at a time, say exactly what they should see, and wait for "done" before the next step. If a screen doesn't match, ask them to describe it or send a screenshot. Only go on when they confirm they see what you said they'd see. A pasted link, a guess or anything unclear isn't proof that a step worked or that a page exists: ask what the page shows (its title, or a screenshot). You can't see GitHub, so don't guess why something happened. Whenever you open a web page for them, also put its full address in your message as a clickable link, so they can open it again themselves (for example after signing in to a different account).

If they get a 404 (page not found), ask which address is in the address bar, then check one at a time: Are they signed in to GitHub? As the right account (the round picture at the top right shows it)? Has the repository been made yet (github.com/<username>?tab=repositories lists it)? For the live link, Pages can take up to ten minutes after step 8. Are the username and repository name spelled exactly right? If the template link still gives a 404 once they're signed in, the template may be private or gone: tell them to let whoever gave them the kit know, and stop instead of retrying.

1. Check that version 1 works and is saved. If not, suggest finishing first.
2. Explain in three sentences: GitHub stores the project online and keeps every version. GitHub Pages turns the docs folder into a live link. On a free account the project is public, so anyone with the link can read the files, including notes and reviews.
3. Privacy check of every file that will be uploaded (CLAUDE.md, NOTES.md, HABITS.md, reviews/, docs/). List anything private and fix it with them before going on. For each photo in docs/, ask if it came straight from a phone, unless they already told you this session. If so, have them drag a screenshot of it into docs/, set the original aside, and point the page at the new file.
4. GitHub account: open github.com/signup in their normal browser. "Continue with Google" or Apple is fine. Their username will be in the page's link, so pick one they're happy to share. Verify the email. Ask which username they chose. If it matches the owner in the brief footer's template link, ask again: that account holds the kit, not theirs. If they already had an account, ask if they're happy for that username to be in a public link. If they're signed in to more than one GitHub account, have them sign out of the others first.
5. Make their project from the template. First say in one line: the template's address shows the kit's account, and their copy will be under their own name. Open the template link from the brief's footer with /generate added to the end: it goes straight to the "Create a new repository" form. If it shows a 404 or a sign-in page, they sign in and open it again. Check the Owner box shows their username (if not, pick it from the list there). Name it (for example my-page), choose Public, and click the green "Create repository" button. Wait until GitHub opens <username>/<repo-name> by itself, with a list of files (CLAUDE.md, docs and so on): typing that address before then gives a 404, because the copy doesn't exist yet. Use the name in that page's title from here on.
6. Update "Where it lives" in CLAUDE.md to "GitHub: <username>/<repo-name>". Leave Session number as it is: the cloud session they start at the end is still this session, not a new one, and /wrapup there adds 1. Also add "commit", "branch", "GitHub Pages" and "cloud session" (Claude working on your GitHub copy online, not the folder on your computer), plus any other word you'll use in steps 7 to 12, to "Words I've learned" now, with a one-line meaning each, since nothing written in this folder after the upload reaches GitHub, and add a line to the log in NOTES.md: "Level 2: moved to GitHub, live at https://<username>.github.io/<repo-name>/." Add one line under "Today" for each notable move so far, starting with the session number (for example "S2:"), so the review in the cloud session can use them. Also write any habit counts or traps you're still holding into HABITS.md now, and add one "Today" line with this session's counts so far, for example "S2 counts so far: plan 0 own/1 reminded; check 1/0; save 0/1; goback 0/0". Also add a "Today" line "S<N>: /level-up in progress on the computer, next step 7 (a Cloud session reading this can skip it: the upload is done). After it, in the first Cloud session: one small change, /save, /ship, then /wrapup to finish session <N>." (it goes up with the files, which does no harm). Do this before the upload so it goes with it. (Ask permission like any file change.)
7. Upload: first offer to open this project folder for them in Finder (Mac) or File Explorer (Windows). That takes one permission box (if it doesn't open, use the level 1 fallback in .claude/CLAUDE.md). In the new repository click "Add file", then "Upload files". From inside the project folder, drag in CLAUDE.md, NOTES.md, HABITS.md and the reviews and docs folders. Don't drag the project folder itself: that puts everything one folder too deep. Don't upload versions or set-aside. Click "Commit changes". Then ask them to click CLAUDE.md on GitHub and check two things: "Where it lives" says GitHub:, and their own answers are there. If they see blanks (____), the upload went wrong. Upload the files again from inside the folder. Then remove the misplaced extra folder, because it also holds versions and set-aside, which weren't privacy-checked: open that folder on GitHub, click the three dots (...) at the top right, choose Delete directory, then Commit changes. Their files are still safe in the folder on their computer. If versions/ or set-aside/ there held something private (for example the original phone photo from step 3), tell them GitHub's history still keeps a copy. The only full fix is to delete the repository (Settings, bottom of the page, Delete this repository), make it again (step 5) and upload again (this step). Step 6 is already done: only if they pick a different name, change "Where it lives" and the "Level 2: ... live at" log line in NOTES.md in that same change. Once CLAUDE.md looks right on GitHub, the notes and scorecard have gone up. For the rest of this session here, don't count habits or note moves, and don't ask them to remember any for /wrapup. Praise good moves in the moment instead.
8. Turn on the site: Settings, then Pages, then under "Build and deployment" choose "Deploy from a branch", branch main, folder /docs, Save. It can take up to ten minutes.
9. Their link is https://<username>.github.io/<repo-name>/ . Ask them to open it on their phone.
10. Connect GitHub to Claude: open https://claude.ai/code in their normal browser and follow the "connect GitHub" prompt. If no prompt appears, open https://claude.ai/connect-github directly. That page also shows which GitHub account is connected: it must be <username>, the new one. If it shows another account, ask for a screenshot and help them switch instead of guessing. If it offers to install the Claude GitHub App, choose "Only select repositories" and pick <repo-name> only. Don't take "done" as proof: step 12 checks that the repository shows up.
11. Before they leave this session, say: from now on you work in a cloud session on <username>/<repo-name>, on the computer or the phone. This folder is now the old copy: nothing changed here reaches GitHub, so don't build, /save or /wrapup here. After this session, rename the folder to "<repo-name> (old copy)". The new session is a fresh chat that won't remember this one, but it reads your notes. Ask: "Carry on now, or stop for today?" Either way, give step 12, so they know the way back.
12. First ask one question: where will you work next, in the Claude desktop app, on the web or on the phone? Give only that one's clicks. If they carry on now, give them one at a time and wait for "done" after each. If they stop for today, give them as one short numbered list they can follow next time, and don't wait for "done". Desktop app: the Code tab, start a new session, set the environment to Cloud, pick <username>/<repo-name>. Web: https://claude.ai/code, pick the repository, start a session. Phone: the Claude app, then Code, pick the repository, start a session. If the repository isn't in the list, GitHub didn't connect: open https://claude.ai/connect-github and ask which GitHub account it shows. If it isn't <username>, ask for a screenshot and help them switch first (as in step 10). Then install the Claude GitHub App on <repo-name> only ("Only select repositories") and try again. Then say only: "Your first message in the new session is /pickup. It tells you where you are and one small next step." If they carry on now, ask them to keep this session open until /pickup has answered there. Don't change any files here after that.
