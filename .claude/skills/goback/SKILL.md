name: goback
description: Put the page back to a saved version without deleting anything.
disable-model-invocation: true
---

Only the website (the docs folder) goes back. The brief, NOTES.md, HABITS.md and reviews/ stay as they are, so the scorecard and log keep counting.

1. Read "Where it lives" in CLAUDE.md. If it starts with "GitHub:", use only the level 2 steps: saves are commits, and versions/ isn't used. At level 1, first check these in order and use only the first that fits:
   (a) The brief is still blank (____): say there's nothing to go back to or undo yet, because the page hasn't been built, and suggest /start. Don't mention /rewind or fixing anything. Stop this command.
   (b) There's no versions/ folder or it's empty: say plainly that nothing has been saved yet, so there's no version to go back to. Then offer the ways out: we fix it together one small step at a time, and, only if you changed files in this session, typing /rewind to undo those changes. Stop this command.
   (c) Otherwise, go on.
   List the saved versions, newest first, in plain words: at level 1 the folders in versions/ with their NOTES line; at level 2 the recent saves (commits) on GitHub with their labels. At level 2, the "Add files via upload" save(s) from the /level-up day are the version they put online then (if there are two, the newer one is the corrected upload). Later saves with that name are files they uploaded on GitHub (for example a photo), so describe each one by what it added, not by its name. Saves from versions/ on their computer didn't come along.
2. Ask which one to go back to. Suggest the newest save whose page is different from the page now. If the newest save matches the current page, that is usually the one before it.
3. Before changing anything, compare the current docs/ with that version's docs/ with a command that includes hidden files: at level 1, diff -r docs versions/NN-label/docs (on Windows, git diff --no-index --stat docs versions/NN-label/docs if git is there, otherwise Get-ChildItem -Recurse -Force on both folders, then read the files that differ); at level 2, git diff <that save> -- docs. Base what you say only on that output. Tell them in plain words what will come back and everything they'll lose from the current page, including changes that were never saved. At level 1, changes that were never saved leave the page, but they're kept in set-aside/ with everything else. At level 2, a change that was never saved is gone for good, so say that plainly and offer /save first. docs/.nojekyll is a hidden kit helper file that every save copies. Don't mention it unless they ask.
4. When they say yes:
   - Level 1: first move the current docs/ folder inside a new folder set-aside/NN-before-goback (NN is the next free number), so it ends up as set-aside/NN-before-goback/docs. Make the folder and move docs in one command line, for example mkdir -p set-aside/NN-before-goback && mv docs set-aside/NN-before-goback/ (on Windows, New-Item -ItemType Directory -Force set-aside/NN-before-goback; Move-Item docs set-aside/NN-before-goback/). Moving and copying back both need a terminal command, so say so before each permission request. Moving isn't deleting: everything is still there in set-aside/. Then copy that version's docs/ back into the project with one copy command (cp -R, or Copy-Item -Recurse on Windows), so pictures come back too and the page matches the save exactly. Never delete anything. If you say how many boxes to expect, count the NOTES.md line from step 5 too, by the box rule in the Coach style.
   - Level 2: make a new save that puts docs/ back exactly the way it was in that version, including taking out files that version didn't have (for example with git restore --source=<that save> --staged --worktree -- docs). History keeps everything; nothing is rewritten. Before you commit, add the NOTES.md line from step 5 now (not again later), so it goes in the same commit. Check every changed file for anything private. Then commit with the label "back to <label>". If that label is "Add files via upload", or another save has the same label, use plain words instead, for example "back to before pots photo" or "back to level-up version". Push it on this session's branch (never force, never to main). This isn't a /save: don't add a save line and don't count habit 6. Then say: "Saved on GitHub, not live yet. /ship puts it live."
5. Add a line to NOTES.md saying which version you restored and why. (At level 2 you already did this in step 4.)
6. For this session's HABITS line, count it as goback "own" if they typed /goback without you suggesting it in your reply just before, otherwise "reminded". Note it in your moves log.
7. Give "What changed:" and "Check it yourself:" as after any change: ask them to look at the page and confirm it's how they remember it (at level 2, on the live link once they've merged it with /ship). At level 2, if you say what "Files changed" will show, it shows only what's different from the live page: run git fetch origin, then git diff origin/main...HEAD, and describe that. A change that was never saved was never live, so it won't be there. At level 2, don't suggest /save: the goback is already saved, so point to /ship. Then, in one or two sentences, explain what probably went wrong in the version they left behind. From session 3, if you've already given the /plan-it reminder this session, don't name /plan-it or tell them to plan next time here; the build review at /wrapup covers it.
